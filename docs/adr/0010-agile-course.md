# ADR 0010 — 学習アプリに「アジャイル・スクラム編」をコースとして足す

- ステータス: 承認済み（2026-09-26）
- 関連: [0009](0009-learning-app.md)（学習アプリの形式。これを拡張する）、
  [brainstorm.md](../brainstorm.md) 2026-09-26「アジャイル・スクラム編」

## 背景

ADR 0009 の学習アプリ（26 章・7 部）は REST API の設計を学ぶためのもの。利用者から
「同じ HTML の形を踏襲しつつ、アジャイル開発・スクラムの知識も学べる教材にしたい」という要望が出た。

利用者の条件（壁打ちで合意）:

- 目的は**現場でスクラムを回せること**。資格対策（スクラムガイドの文言暗記）はしない
- 読者は**ウォーターフォールの経験がある**
- 範囲は**アジャイル・スクラムの基本が伝わる最小限**。必要ない知識は思い切って削る
- 実務重視なので、契約（請負と準委任）は入れる

## 決定

### 構造: 同じアプリで「コース」を切り替える

| 項目 | 決定 |
|---|---|
| 画面 | `index.html` を共有し、ヘッダーでコース（REST API / アジャイル・スクラム）を切り替える |
| URL | API 編は従来どおり `#ch/3`。アジャイル編は `#agile/ch/3`、ホームは `#agile` |
| 章ファイル | `chapters/agile/outline.js`（目次）＋ `chapters/agile/chNN.js`。`Calc.register({ course: "agile", … })` |
| 進捗 | 保存データは 1 つ（`calcLearning.v1`）のまま、アジャイル編の鍵に `agile:` を付ける（`passed["agile:3"]`、問題 id `agile:3:…`）。**API 編の既存データの形は変えない**ので、書き出した古いファイルもそのまま読める |
| 章の解放 | コースごとに独立（API 編を終えなくてもアジャイル編を進められる）|
| 共有するもの | 図の部品（`Fig.*`）、出題・採点・苦手の優先出題、書き出し・読み込み、リンク検査（`LearningLinksTest`）|
| 章の型の追加 | `wf:` 欄「ウォーターフォールではこうだった」。**アジャイル編では必須**（自己検査で無ければ警告）|

「実物」はコードではなく、このリポジトリの `docs/`（spec.md の受け入れ基準と「今後の候補」、CLAUDE.md の DoD、
progress.md、learning/sprint-N.md、ADR）と git のタグ。**このリポジトリの Sprint は厳密なスクラムではない**
（期間で区切っていない・利害関係者がいない・一人＋AI）ことも、正直に教材として扱う。

### 章立て（9 章・4 部）

| 部 | 章 | テーマ | 種別 |
|---|---|---|---|
| 1 アジャイルとは | 1 | なぜアジャイルか：ウォーターフォールとの違い、アジャイル宣言 | 実物＋座学 |
| 2 スクラムの仕組み | 2 | 全体像：スプリントというループと経験主義 | 座学 |
| | 3 | 3 つの責任：PO・スクラムマスター・開発者 | 実物＋座学 |
| | 4 | 5 つのイベント | 実物＋座学 |
| | 5 | 3 つの作成物と確約（プロダクトゴール・スプリントゴール・DoD）| 実物 |
| 3 バックログを回す | 6 | プロダクトバックログの育て方：ストーリー・分割・受け入れ基準・リファインメント・並べ方 | 実物＋座学 |
| | 7 | 見積もりと計画：相対見積もり・ベロシティ・バーンダウン | 座学 |
| 4 現場で | 8 | よくある失敗と、ウォーターフォールの組織で始めるとき（契約）| 座学 |
| | 9 | このリポジトリを振り返る ＋ まとめ | 実物 |

内容はスクラムガイド 2020 年版に合わせる。スクラムガイドに無いが現場でよく使う道具
（ユーザーストーリー・ストーリーポイント・バーンダウン）は「補完的なプラクティス」と明示して扱う。

## 影響

- `LearningLinksTest` が `chapters/agile/` の章ファイルも検査する（リンク・読み込み漏れ・行番号の一覧）
- 9 章 × 15 問以上 ≒ 140 問を追加
- API 編の本文・問題・保存データには手を入れない

## 不採用案

| 案 | 不採用の理由 |
|---|---|
| API 編の第 8 部以降として同じ目次に足す | 章の解放が 1 本の直列になり、API 26 章を終えるまでアジャイルに進めない |
| HTML を複製して別アプリにする | 図の部品・出題・保存の仕組みを二重に保守することになる |
| 保存データを別の鍵（`calcAgile.v1`）に分ける | 書き出し・読み込みが 2 つになる。1 つのファイルで両コースを移せる方が扱いやすい |
| 18 章版（XP・カンバン・ADR・スケーリング・MVP 手法を独立章に）| 利用者の方針「基本が伝わる最小限」に反する。XP・CI は API 編 20〜23 章にリンク、カンバンは名前だけ触れる |
| 資格（PSM I など）対策の問題 | 目的は現場で回すこと。用語の暗記より状況判断を問う |
