# ADR 0009 — 学習教材を「教科書 ＆ 問題集」の HTML アプリにする

- ステータス: 承認済み（2026-09-26）
- 関連: [0007](0007-reintroduce-model-and-database.md)、[0008](0008-rest-api-finishing.md)（教材の題材となる実装）

## 背景

既存の `docs/learning/textbook.md`（12 章）と `docs/learning/curriculum.md`（Sprint 9 で削除。git の履歴には残る）は Sprint 5 時点
（DB なし・POST が 200）の内容で、Sprint 6〜7 の実装と食い違っている。また読むだけの資料で、
理解度を確かめる仕組みが無い。

利用者の要望:

- この API を題材に、**何度も復習できる**教科書 ＆ 問題集にしたい
- 章ごとに関連クラスへのリンクを張り、**実物を見ながら理解**する。実装と紐づけられる部分は必ず紐づける
- 章末に 4 択で確認し、**9 割以上正解で次の章に進める**
- AI 駆動開発が前提なので、実装の細部より**アーキテクチャと設計の大局**に絞る
- IT の前提知識ゼロから読める
- 実装に無い必須知識（DB の接続、Docker、CI/CD、OpenAPI、最低限のアノテーション、セキュリティなど）も座学で扱う

## 決定

### 形式と置き場所

| 項目 | 決定 |
|---|---|
| 形式 | HTML アプリ（外部ライブラリなし）。`file://` で直接開いて動く |
| 置き場所 | `docs/learning/index.html`（アプリ本体）＋ `docs/learning/chapters/chNN.js`（章ごとの本文と問題）。**コミットする** |
| 進捗 | `localStorage`（章の解放状態・最高点）。リセットボタンあり。使えない環境でも落ちない |
| コードへのリンク | 「VS Code で開く」（`vscode://file/<リポジトリの場所>/<パス>`）＋「GitHub で見る」（`hiropon0216/springboot_API` の main）。リポジトリの場所は画面で変更できる |
| リンク切れ対策 | リンクは「ファイルパス ＋ 目印の文字列」で持つ。**JUnit テスト**が章ファイルを読み、全リンクのファイルと目印が実在するかを検査する（`./mvnw verify` と CI に乗る）|

### 章の型（全章共通）

1. **地図** — この章が全体のどこか
2. **実物を見る** — リンクから開き、問いの形で確認する（実装がある章では必須）
3. **動かして観察** — api-console / curl / テスト実行。期待する出力を先に示す
4. **設計判断** — なぜこうしたか、不採用案（ADR へのリンク）
5. **AI 駆動の観点** — AI にどう頼むか、AI の出力のどこを疑うか
6. **4 択テスト** — 15〜20 問のプールからランダムに 10 問、**9 問以上で次の章が解放**。選択肢はシャッフル。
   不正解には解説と根拠（節・コード）へのリンク。合格済みの章はいつでも再受験できる

出題は用語の暗記ではなく、**状況を与えて設計判断を問う**形を主にする。

**座学の章**（実装に無い知識）は「座学」のバッジを付け、HTTP のやり取り・設定例・コード例などの実例で解説する。
その場合も「このリポジトリに入れるならどこに何が増えるか」を実物のリンクで示す。

「外側（契約）→ 内側（構造）」の順にするのは、AI 駆動開発では人間が主に決めるのが外側
（URL・ステータス・エラーの形）で、内側の実装は AI に任せることが多いから。
先に「決める側の知識」、次に「AI の出力を見抜く知識」の順で学ぶ。

## 影響

- 約 26 章 × 15〜20 問 ≒ 450 問。分けて作る（Sprint 8 = 骨格 ＋ 第 1 部。以降は部ごと）
- 実装を変えたら、関係する章の本文・問題・リンクも更新対象になる（リンク切れは JUnit が検出）
- `textbook.md` / `curriculum.md` は全章が揃った時点で削除する（git の履歴には残る）

## 不採用案

| 案 | 不採用の理由 |
|---|---|
| Markdown の教科書 ＋ 別の HTML 問題集 | 利用者の選択。読む場所と解く場所が分かれる |
| すべて Markdown（答えは折りたたみ）| 9 割ゲートを強制できない |
| 1 つの HTML にすべて埋め込む | 数千行になり、差分レビューができない |
| 行番号でコードにリンクする | コードを直すたびにずれる。目印の文字列で持ち、テストで検査する |
| 章ごとに 10 問固定 | 繰り返すと答えを覚えてしまう |
| 学習済みの問題を出題しなくする方式（BKT など）| 利用者の要望は「章ごとに 9 割で次へ」というゲート方式 |
| 座学を最後の部にまとめる | 文脈から切り離される。関係する部の中に置く |
| 冪等性・同時更新（ETag・Idempotency-Key）の座学 | 利用者の選択で除外 |
