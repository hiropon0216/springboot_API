# Sprint 9 学習ノート — 教材を書き切る・学習を記録する

対象: 2026-09-26 / 決定は [ADR 0009](../adr/0009-learning-app.md)

この Sprint では、学習アプリの残り 22 章と、学習の記録（正誤・受験の記録・復習・書き出し）を作った。
学んだのは「大量の文書を、実物とずれないように書く」ことと「学習者のデータを壊さない」こと。

## 1. 概念の核心

### 1.1 書いたことは、実物で確かめる

本文に「こうなる」と書いた挙動は、実際にアプリを動かして確かめた。確かめたら違っていたものがある。

| 書いたこと | 実際 |
|---|---|
| `/actuator/health` は `{"status":"UP"}` を返す | `{"groups":["liveness","readiness"],"status":"UP"}`。Spring Boot 4 が liveness / readiness を用意していた |
| 第 2 章：verify は「コンパイル → テスト → 検査 → jar」 | 実際は「Checkstyle（validate）→ コンパイル → テスト → jar → Spotless（verify）」 |
| 第 24 章：DB の環境変数が無い prod プロファイルで起動すると失敗する | Docker の有無で失敗の理由が変わり、言い切れない → 確実に確かめられる手順に差し替えた |

**AI が書いた文章も、人が書いた文章も、実物で確かめるまでは仮説**。第 25 章の「正直さ」を教材づくりでも守った。

### 1.2 テストが見逃すずれは、目で見る

`LearningLinksTest` は「目印がファイルの中にあるか」を確かめるが、「狙った行か」までは分からない。
194 か所の目印が指す行を一覧にして目で確かめたら、`needs: build` が設定の行ではなくコメント行を指していた。
→ YAML・Dockerfile の `#` コメントを避けるようにテストを直した。**機械が見逃す種類のずれは、仕組みを直して次から機械が見られるようにする**。

### 1.3 学習者のデータは壊さない

- 保存の形を広げても（`attempts` / `qstats` を追加）、**古い形の保存データを読めるようにした**（足りない項目は空で補う）
- 読み込みは**形を確かめてから置き換える**。壊れたファイルでは何も変えない
- 問題の識別子を「問題文のハッシュ」にしたので、問題の順番を入れ替えても記録はずれない。ただし問題文を直すと別の問題になる（トレードオフ）

### 1.4 「間違えた問題を優先」は確率で確かめる

重み付きの抽選は、1 回だけ見ても正しいか分からない。300 回抽選して「間違えた 2 問が両方出る割合」を数えた（93%、一様なら約 29%）。
**乱数を含む機能は、統計で確かめる**。

## 2. つまずいたところ

- **目印にエスケープした `"` を使った**（`"checks=\"MethodName\""`）。正規表現が目印を途中で切るので、`'…'` で囲む約束にし、テストでも検出するようにした
- **テンプレート文字列の中の `${DB_HOST}`**。本文は JavaScript のテンプレート文字列なので、`${…}` をそのまま書くと式として評価される。図の部品に渡す普通の文字列（"…"）の中なら問題ない
- **エスケープし忘れた `<>`**。`new PagedModel<>(…)` の `<>` を HTML にそのまま入れていた。`&lt;&gt;` にする

## 3. 復習問（答えは下）

1. 本文に「こうなる」と書いた挙動を、実際に動かして確かめる理由は？
2. `LearningLinksTest` が通っていても残りうる「ずれ」は何？ どう見つけた？
3. 保存データの形を変えるとき、何に気をつける？
4. 乱数を使う機能（重み付きの出題）が正しく動いているかは、どう確かめる？
5. 問題の識別子を問題文のハッシュにした利点と欠点は？

### 答え

1. 書いた人（AI も人も）の思い込みが混ざるから。実際に health の応答や verify の順番が違っていた。
2. 目印は存在するが、狙った行ではない行（コメントなど）を指すずれ。全目印の行を一覧にして目で確かめて見つけ、テストの側を直した。
3. 古い形のデータも読めるようにする（足りない項目を補う）。読み込みは形を確かめてから置き換え、壊れていたら何も変えない。
4. 何百回も試して割合を数える（統計）。1 回の結果では判断できない。
5. 利点：問題の順番を入れ替えても記録がずれない。欠点：問題文を直すと、その問題の記録は別の問題として扱われる。
