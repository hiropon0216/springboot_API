# Sprint 8 学習ノート — 教材を「壊れない教材」にする

対象: 2026-09-26 / 決定は [ADR 0009](../adr/0009-learning-app.md)

この Sprint では API ではなく教材（[index.html](index.html)）を作った。学んだのは教材の中身より、
**コードと一緒に育つ文書をどう保つか**という設計の話。

## 1. 概念の核心

### 1.1 文書はコードより先に腐る

旧 `textbook.md` は Sprint 5 で書き、Sprint 6〜7 で実装が変わった時点で、中身が黙って嘘になった
（「POST は 200」「`@Transactional` は無い」）。**文書が古くなっても、誰も気づかない**のが問題。

### 1.2 「気づける仕組み」を機械に持たせる

教材からコードへのリンクを「ファイル＋目印の文字列」で持ち、`LearningLinksTest` で毎回検査するようにした。
コードを直して目印が消えれば `./mvnw verify` が赤くなる。ArchUnit で層を守るのと同じ発想で、
**人の注意力ではなく、テストで守る**。

| 何が古くなるか | どう気づくか |
|---|---|
| リンク先のファイルが消えた・目印の行が無くなった | `LearningLinksTest`（ビルドが赤）|
| 行がずれて「VS Code で開く」の行番号が違う | 同上（`anchors.js` が古いと赤）|
| 新しい章ファイルを `index.html` に登録し忘れた | 同上 |
| 章データの形が崩れた（選択肢が 3 つ、問題が 15 問未満など）| 画面上部の赤い警告（アプリの自己検査）|
| **本文の説明そのものが実装と食い違う** | 機械では気づけない → 実装を変える Sprint で、関係する章を読み直す |

最後の行が限界。機械で守れる範囲と守れない範囲を分けておくのが大事。

### 1.3 ブラウザからはローカルのファイルを読めない

`file://` で開いたページからは、リポジトリのファイルを読んで行番号を数えることができない（ブラウザの安全装置）。
そこで行番号はテストの側で計算して `anchors.js` に書き出し、ページはそれを読むだけにした。
「実行時に分からないことは、ビルド時に計算しておく」という典型的な分担。

## 2. つまずいたところ

- **目印がコメントにも出てくる**: `@Transactional(readOnly = true)` は javadoc にも書かれている。
  Java ファイルでは「コメント以外の行を優先」するルールにした（javadoc の表を指したいときはコメント行でも拾える）。
- **目印に `"` を含めたい**: `@RequestMapping("/api/v1/calculations")` のような行。章ファイルでは `'…'` で囲めば書けるようにした。
- **実験の説明は実際に試す**: 第 3 章「`@Service` を外すとテストが落ちる」を実際に試したら、教材のリンク検査も一緒に落ちた
  （教材が指している行を書き換えたから）。試さずに書いていたら、学習者が混乱するところだった。

## 3. 復習問（答えは下）

1. 文書（教材・README など）が古くなることの一番の問題は何？
2. 教材のリンク切れを「人が気をつける」ではなく、テストで検出するのはなぜ？
3. `LearningLinksTest` で検出できない「古さ」は何？ それにはどう対処する？
4. 行番号を HTML の中で計算せず、`anchors.js` に書き出しているのはなぜ？
5. 4 択の出題を毎回ランダムにし、選択肢の順番も混ぜているのはなぜ？

### 答え

1. 古くなっても誰も気づかないこと。読んだ人は嘘を正しいと信じてしまう。
2. 人の注意力は抜ける（特に AI が大量に変更するとき）。テストにすれば、壊した瞬間にビルドが赤くなり、誰でも気づける。
3. 本文の説明が実装と食い違うこと（リンク先は存在するが、書いてある説明が古い）。実装を変える Sprint の Definition of Done に「関係する章を読み直す」を含めて対処する。
4. ブラウザは `file://` のページからリポジトリのファイルを読めないから。ビルド時（テスト）に計算して書き出しておく。
5. 同じ 10 問を同じ順番で繰り返すと、内容ではなく答えの位置を覚えてしまうから。
